## Context

当前系统已经通过 `kinematics_visuals` 生成身体姿态、上肢和下肢相关的 annotated keyframe，并将其作为 `ReportAsset` 投影到 `swim-report.v1`。后端资产已具备 `artifact_key`、`module_key`、`metric_keys`、`annotation_frame`、`source_video_frame`、数值和来源 revision 等信息，但前端归一化层只保留了少量通用字段，页面也没有对关键帧做有语义的分组展示。

报告固定为五页，页面 2 至 4 分别负责身体姿态、上肢和下肢模块。该变更应复用现有页面和资产生成链路，避免新增页面或改变指标计算；关键帧仍然表示指标极值或检测到的运动学事件，不被解释为完整动作阶段。

## Goals / Non-Goals

**Goals:**

- 在报告 API、前端 view model 和打印页面之间保留完整的关键帧展示元数据。
- 在页面 2 至 4 以稳定顺序展示与当前模块相关的自动诊断关键帧。
- 让每张关键帧图片能说明“是什么指标、什么诊断含义、数值是多少、来自哪一帧”。
- 在资产缺失或降级时保留结构化提示，不让单个关键帧失败阻塞报告。
- 保证 Web 报告和 PDF 使用相同的关键帧集合和语义信息。

**Non-Goals:**

- 不识别或推断入水、抱水、推水、出水、移臂等动作阶段。
- 不增加新的运动学指标、诊断规则或视频机位。
- 不改变五页报告、现有 artifact generation signature 或数据库表结构。
- 不进行像素级 PDF 快照锁定；只验证结构、内容和可读性。

## Decisions

### 1. 复用现有 annotated keyframe 资产

报告只消费 `artifact_type = annotated_keyframe` 且状态为 `ready` 的现有资产。关键帧的选择继续由 `frame_selection.py` 完成，报告层不重新根据原始时序计算极值。这样可以保证图片、指标和 artifact manifest 使用同一 source revision。

备选方案是报告页面实时从视频截帧。该方案会重复帧映射、骨架叠加和存储逻辑，容易造成 Web/PDF 不一致，因此不采用。

### 2. 使用稳定的语义映射替代原始 artifact key

后端保留原始 `artifact_key` 作为追溯标识，同时提供展示用的 `title`、`label`、`metric_label`、`unit`、`selection_reason` 和 `caption`。展示文案集中在后端 presentation registry，前端只负责布局，避免前端根据字符串拆分 key 推断业务含义。

备选方案是直接显示 `body_axis_max` 等技术 key。该方案对开发者可读，但不适合教练和 PDF 读者，也无法稳定表达“最大值/最小值”的含义。

### 3. 页面按模块分组，关键帧优先于图表

页面 2 至 4 的资产排序由现有 `PAGE_ASSET_ORDER` 扩展：先显示代表性关键帧，再显示时序图和轨迹图。每个页面最多展示该页既定资产计划中的关键帧，避免把全部左右侧极值资产无差别铺满页面。页面 3 和页面 4 可以继续使用跨侧选择逻辑，展示最具代表性的屈曲/伸展或屈膝/伸展证据。

备选方案是新增“关键帧总览”第 6 页。该方案会破坏五页 PDF 契约，且把证据与对应模块分离，因此不采用。

### 4. 前端保留完整字段但保持向后兼容

`normalizeReportData` 为资产补充可选字段；旧报告缺少这些字段时仍按通用图片资产渲染。关键帧组件根据 `artifact_type` 或 `type` 判断展示模式，普通图表资产继续走现有路径。

### 5. 中文字体和标题由渲染器统一处理

关键帧图片内嵌标题和数值时使用项目可用的中文字体或可靠字体回退，并对文案做 ASCII/Unicode 字体可用性测试。图片内的信息保持简短，完整解释放在报告卡片中，避免图片标题过长导致截断。

## Risks / Trade-offs

- [关键帧数量增加导致页面拥挤] → 使用页面资产排序和模块级展示上限；打印布局预检发现溢出时失败并报告页码。
- [部分资产缺少指标值或帧映射] → 展示 `N/A` 和结构化质量说明，禁止伪造帧号或数值。
- [历史报告数据没有新增字段] → 新字段全部可选，保留旧资产渲染回退。
- [中文字体在 CI/Playwright 环境不可用] → 将字体回退链和关键帧图片文字可读性加入渲染测试，不依赖单一本机字体。
- [跨侧选择后无法直观看出左右来源] → 在展示元数据中保留 `selected_side`、原始 artifact key 和 source frame。

## Migration Plan

不需要数据库迁移。部署顺序为：先部署后端展示元数据和前端兼容读取，再启用新的报告布局；历史 artifact 可在读取时按已有 metadata 回退，重新生成时获得完整文案。若打印布局出现回归，可暂时关闭关键帧证据区域的展示开关，恢复为现有资产网格，生成链路和数据库数据不受影响。

## Open Questions

- 关键帧图片内嵌标题是否需要统一为中英文双语，还是只保留中文。
- 页面级关键帧上限是否固定为 3 张，还是根据页面可用高度配置。
