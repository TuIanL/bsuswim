## Context

现有 AI 解读将 `swim-report.v1` 投影为结构化 `facts`、有限上下文和按标签检索的知识条目，再以纯文本 JSON 调用 DeepSeek。该路径能以本地 schema、引用和数值护栏保证叙述不篡改确定性运动学事实，但模型看不到五页报告中已有的关键姿态资产与时序图，且知识库规模有限，导致解释缺少动作证据上下文。

本变更替换 provider 为 Qwen 兼容 API，并在不传输原始视频、完整标注和全量逐帧关键点的前提下，向具备视觉能力的模型传递最小化视觉证据。教练、运动员和运营方需要可读的解释；工程和数据治理责任人需要可复现、可审计、可关闭的外部数据传输。

## Goals / Non-Goals

**Goals:**

- 支持通过服务端配置调用 Qwen 兼容 API，且不暴露或持久化 API key。
- 从已持久化、当前 revision 的报告资产中为每个模块选择有限的关键帧和时序图，并让视觉模型以事实 catalog 为唯一数值与结论依据。
- 在模型不支持图片输入或视觉资产不可用时稳定降级到当前文本事实解读。
- 将证据清单、模型能力、输入 hash 和资产版本纳入签名、审计、失效与评测。

**Non-Goals:**

- 不上传原始视频、视频片段、全量标注、全量逐帧关键点、用户身份信息或存储绝对路径。
- 不让大模型重新计算运动学指标、替换规则阈值、输出医学诊断或综合技术评分。
- 不在本变更中进行模型微调、自由问答、自动训练计划或扩大五页基础报告的页数。
- 不假定 `qwen-plus` 本身支持图片输入；实际能力以部署探针和 provider 适配结果为准。

## Decisions

### 1. 使用能力显式的 Qwen provider 配置

新增 Qwen/OpenAI-compatible adapter 和配置项，模型、endpoint、API key、`vision_enabled` 与结构化输出能力均由服务端管理。启动/首次调用时以非敏感能力探针或受控配置验证所选模型；当模型不支持图像消息或严格 JSON 输出时，记录能力结果并只发文本证据包。

备选方案是把 `qwen-plus` 直接硬编码为视觉模型；这会在能力不匹配时静默丢失图片或请求失败，故不采用。保留 provider 接口可以继续支持文本模型和后续视觉模型切换。

### 2. 构建独立的 `MultimodalEvidenceBundle`

在 `project_report` 之后、provider 调用之前构建证据包。它只引用当前报告 section 的资产：每个技术模块最多 2 张关键姿态图和 1 张时序/趋势图，全报告有数量、像素、字节和总请求上限。每个项目包含稳定 evidence ID、asset ID、模块、媒体类型、MIME、内容 hash、关联 `fact_refs`、关联 finding、帧/曲线范围和选择理由；二进制图片只在调用时读取，不写入数据库。

曲线同时保留限长、下采样的数值摘要，包含单位、时间/帧坐标、缺失段和采样规则。选择现有派生报告资产而非重新渲染或上传原图，可以复用权限、revision 和生成签名；备选的“把所有图片与全量序列发送”会增加隐私、成本和噪声，不采用。

### 3. 请求采用 JSON 事实 + 图像内容分段

文本部分仍是版本化 `InterpretationInput`，加入 evidence manifest；视觉 provider 请求按其兼容 API 的多段 message 格式发送 JSON 事实和内联/短时签名 URL 图像。provider adapter 负责格式差异，业务层不依赖厂商字段。文本模型只接收同一 input 的文本投影，图片及其视觉可见性状态不伪造为已分析。

模型输出 schema 增加可选 `evidence_refs`，但技术解释仍必须有 `fact_refs`；本地校验拒绝不存在的 evidence 引用、图像推断出的新数值、无事实支撑的断言和诊断措辞。

### 4. 审计签名包含视觉输入而非媒体内容

generation signature 追加 provider/model capability profile、evidence manifest 的稳定 hash 和曲线摘要 schema 版本。审计只保存 manifest、hash、尺寸、选择结果、拒绝原因和用量，不保存 provider 原始请求/响应或媒体二进制。报告 revision、资产 generation signature 或 evidence manifest 变化都使旧解读 stale。

### 5. 渐进发布与离线评测

先以关闭自动生成为默认，在真实去标识化报告上对比文本和多模态输出。通过事实一致性、有效引用、无视觉臆造、教练可读性/可执行性盲评和成本/延迟门槛后，才允许小范围开启自动生成。失败始终不影响基础报告与 PDF。

## Risks / Trade-offs

- [Qwen 模型或 endpoint 不支持图像/严格 JSON] → 部署探针、能力配置和文本降级；不将视觉模式标记为 ready。
- [图像中的文字、坐标或姿态导致模型臆造数值] → 数值只允许由 `fact_refs` 支撑，输出进行数字与引用校验，并加入对抗评测。
- [报告资产 URL 失效或越权读取] → 调用前校验报告所属关系、revision 和存储可读性；使用短时访问方式或内存读取，失败时去除该证据并记录原因。
- [图片过多导致成本、延迟或上下文拥挤] → 模块和总量硬上限、尺寸压缩、预算预检、可观测性及回退。
- [CSV 凭据泄露到日志或 Git] → 仅在本地受忽略环境文件配置，掩码日志；实施前检查 `.gitignore`，绝不回显密钥。
- [视觉说明被误解为诊断] → 延续条件式措辞、禁止词校验和教练试运行。

## Migration Plan

1. 保持现有解读记录、DeepSeek adapter 和文本 schema 可读；新增字段使用默认值，历史记录按文本模式解析。
2. 新增数据库迁移和 Qwen 配置，但默认关闭自动生成；密钥由部署者写入未跟踪的 `backend/.env`。
3. 运行 provider 能力探针、fixture 评测、视觉/文本降级测试和 Web/PDF 回归。
4. 以手动生成方式进行教练试运行，记录质量、失败率、成本和隐私审查结果。
5. 出现事实护栏漏检、provider 异常或成本超限时，关闭视觉与自动开关，保留基础报告和最近一次已验证文本解读。

## Open Questions

- CSV 对应的 Qwen endpoint 与目标模型是否明确支持图片输入和严格 JSON Schema；若仅提供 `qwen-plus`，视觉路径需指定可用的 Qwen 视觉模型。
- 图片传输采用 provider 支持的 data URL 还是短时签名 URL，需按部署网络、对象存储和 API 能力确定。
- 教练盲评的样本量、通过阈值和指定审核人尚未确定。
