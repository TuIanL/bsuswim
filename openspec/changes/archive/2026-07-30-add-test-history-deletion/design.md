## Context

`TrainingSession` 是测试历史的业务根对象，但当前没有删除 API 或前端操作。它关联 `SessionVideo`、`AnalysisTask`、`AnalysisResult`、`ReportMetadata`、标注、标准化标注、指标、复核结论和运动学资产；相关文件分散在上传根目录、`kinematic-artifacts/` 和 `reports/`。部分数据库外键没有 `ON DELETE CASCADE`，直接删除训练记录会失败或遗留数据。

系统以当前登录教练作为资源所有者。分析任务通过 FastAPI `BackgroundTasks` 运行，执行期间删掉任务会与后台写入竞争。原始 `VideoFile` 在模型上允许由多个会话关联，因此不能无条件删除其文件。

## Goals / Non-Goals

**Goals:**

- 让教练从测试任务页和运动员历史中删除自己的一条测试记录。
- 删除关联的数据库记录及可确定归属的磁盘文件，并防止路径越出上传根目录。
- 在删除前阻止非终态分析任务，保证不会产生删除后的回写。
- 通过 API 和前端状态提供可测试、明确的成功与失败反馈。

**Non-Goals:**

- 不提供软删除、回收站、恢复或批量删除。
- 不删除运动员、教练、队伍或其他测试记录。
- 不补偿清理由旧版本或手工创建、且不在数据库中登记的孤立文件。
- 不实现任务取消或分布式后台任务队列。

## Decisions

### 1. 以训练记录为硬删除根，并提供受权的 REST API

新增 `DELETE /api/v1/sessions/{session_id}`。路由先按当前教练校验 `TrainingSession` 的所有权，成功返回 `204 No Content`；找不到或无权访问时返回 `404`，分析任务为非终态时返回 `409 Conflict`。

选择按会话删除而非单独按分析任务删除，因为列表中的一条历史测试由会话、视频和其分析产物共同组成。单删任务会保留视频和历史记录，无法实现用户预期的彻底清理。

### 2. 使用专用删除服务显式编排依赖和文件清单

删除服务在提交前加载完整关联图，收集以下受控路径：`VideoFile.storage_path`、`AnnotationFile.storage_path`、`KinematicArtifact.storage_path` 和 `ReportMetadata.pdf_path`。所有相对路径或绝对路径必须解析到 `settings.upload_dir` 内；拒绝 NUL、绝对越界和符号链接逃逸。运动学资产和 PDF 按收集到的文件路径归并为其专属父目录后删除，原视频和标注按文件删除。

服务按依赖顺序显式删除报告解读与报告、分析结果与任务、复核结论、资产集与资产、指标、标准化标注、标注文件及会话视频，最后删除训练记录。`VideoFile` 仅在删除会话关联后确认没有其他 `SessionVideo` 引用时，才删除数据库记录和原始文件。

不依赖仅有的 ORM cascade 或一次直接 `DELETE`：目前报告和分析任务等关系没有完整的数据库级级联，且数据库 cascade 无法删除磁盘文件。

### 3. 文件清理失败须可见且可重试，不静默报告成功

服务先验证可删除路径并在数据库事务中完成关系删除；成功提交后执行文件删除。文件删除失败时，API 返回服务错误并记录未清理路径，保留一个可重入的清理动作或失败记录，直到文件系统清理完成。实现不得把数据库成功但磁盘失败伪装为完全成功。

文件系统与数据库无法组成单一 ACID 事务。该策略优先保证历史记录不可再被 API 读取，同时使文件残留可诊断、可重试；对“先删文件后删数据库”的替代方案，数据库提交失败会造成仍可见记录指向丢失文件，因此不采用。

### 4. 前端使用危险操作确认并在成功后刷新本地列表

测试任务表每行增加危险样式的删除操作；运动员档案的历史记录复用相同动作。确认框必须展示任务标题并说明会删除视频、报告及分析数据，用户确认后调用 API。按钮在请求期间禁用，成功后重新加载会话和任务；失败时保留当前行并展示后端错误。demo 模式同步从内存会话、任务和视频集合移除对应数据。

### 5. 通过迁移补齐可安全执行的关系约束

新增 Alembic migration，为本功能所需的外键级联策略和清理失败持久化状态（如采用失败记录）建立明确约束/表。应用层删除服务仍为唯一入口，以集中处理文件与共享视频引用计数。

## Risks / Trade-offs

- [后台分析与删除并发] → 仅允许删除 `completed` 或 `failed` 的任务；返回 `409` 指引用户等待结束。
- [磁盘错误导致残留文件] → 路径清单、可诊断失败记录和幂等重试；不得将其报告为完全成功。
- [共享原视频被误删] → 在删除 `SessionVideo` 后重新查询引用数，仅在为零时删除 `VideoFile` 和文件。
- [恶意或损坏的路径值] → 仅接受上传根内、经真实路径规范化验证的路径；任何异常路径中止删除并返回错误。
- [大记录删除耗时] → 前端显示进行中状态；初期保持同步 API，后续可迁移到受监控的清理队列。

## Migration Plan

1. 发布数据库迁移和删除服务，再发布前端入口。
2. 在测试环境以含视频、标注、资产、PDF 和报告解读的会话执行端到端删除验证。
3. 部署后监控删除失败记录和上传目录残留；修复后使用同一清理流程重试。
4. 回滚时移除前端入口和 API 路由；不恢复已硬删除的数据，清理失败记录保留供运维处理。

## Open Questions

- 文件清理失败记录应以独立数据表持久化，还是先以结构化服务日志和管理员重试命令落地？推荐独立表，以满足可见且可重试的承诺。
- 是否要允许删除 `draft` 或仅有视频、但没有分析任务的会话？推荐允许；“非终态禁止”只适用于确实存在且正在运行的分析任务。
